# Визуальный профиль университета

LOCUS Startup Hackathon 2026 — Кейс 01 (`LOCUSCASE1`)

AI-сервис: по названию университета формирует проверенный визуальный профиль
кампуса — фото по категориям, без дублей, с указанием источника и честной
оценкой достоверности.

## Задача

Абитуриент видит красивые рекламные страницы, но достоверные фото кампуса
разбросаны по десяткам источников. Сервис принимает название университета,
находит изображения, проверяет их принадлежность, удаляет дубликаты и
формирует профиль со ссылками на источники.

## Стек

- **Frontend**: Next.js 16 (App Router) + React 19 + Tailwind CSS 4, деплой на Vercel
- **Backend**: Next.js Route Handlers (`/api/search`), serverless
- **Поиск изображений**: Wikimedia Commons API + Openverse API (оба бесплатны, без ключей — фото уже несут источник/лицензию/дату)
- **Дедупликация**: perceptual average-hash (8×8 grayscale, `sharp`) + Hamming distance
- **Верификация принадлежности / категоризация**: Google Gemini Vision (бесплатный ключ, без карты)
- **Описание кампуса**: Gemini (текст) на основе краткого summary из Wikipedia API
- **Разрешение неоднозначных запросов**: Wikipedia Search API (топ-кандидат + альтернативы)

## Архитектура пайплайна

1. `resolveUniversity` — нормализация названия через Wikipedia Search API,
   получение канонического имени и summary; город и страна вытягиваются из
   связанного Wikidata-объекта (P131/P17), список альтернативных совпадений
   (обработка неоднозначных запросов).
2. `searchAllCategories` — широкий пул изображений с Wikimedia Commons и
   Openverse: базовый поиск по названию университета + поиск по городу +
   дополнительные точечные запросы-подсказки по категориям (используются
   только как сигнал для увеличения recall, не как источник истины).
3. `dedupeCandidates` — вычисление perceptual hash для каждого изображения,
   отсев дублей и визуально похожих кадров (Hamming distance ≤ 6/64).
4. `verifyBatch` — Gemini Vision смотрит на каждое оставшееся изображение и
   (а) подтверждает принадлежность университету/городу, (б) сам определяет
   итоговую категорию из содержимого фото (не из поискового хинта), (в)
   возвращает `confidence` (0–1) и текстовое пояснение на русском.
5. Изображения с `confidence < 0.35` скрываются, `0.35–0.6` помечаются как
   низкая достоверность (жёлтый бейдж) — реализация принципа "честная
   неопределённость" из требований кейса.
6. `generateDescription` — краткое факт-ориентированное описание на основе
   Wikipedia summary (без домысливания).

## Запуск локально

```bash
npm install
cp .env.local.example .env.local   # заполнить ключи
npm run dev
```

Откроется `http://localhost:3000`.

## Переменные окружения

См. `.env.local.example`:

- `GEMINI_API_KEY`, `GEMINI_VISION_MODEL`, `GEMINI_TEXT_MODEL` — Google Gemini
  (aistudio.google.com/apikey, бесплатно, без карты)
- Wikimedia Commons и Openverse ключей не требуют.

## Тестовый сценарий

1. Ввести название университета (например, не из демо-видео).
2. Дождаться результата (~10–25 сек в зависимости от числа найденных фото).
3. Проверить: категории заполнены, под каждым фото — % достоверности и
   кликабельный источник, дубликаты отсутствуют, при нехватке данных —
   явное предупреждение сверху.
4. Использовать фильтры по категориям.

## Ограничения

- Дата публикации доступна для фото с Wikimedia Commons (EXIF/метаданные
  загрузки); Openverse дату не всегда предоставляет.
- Скорость поиска зависит от числа найденных кандидатов и задержек внешних
  API (Commons/Openverse/Wikipedia/Gemini).
- Демо ограничено университетами, у которых есть фото на Wikimedia Commons
  или в источниках, агрегируемых Openverse (в основном крупные/известные
  вузы) — честно отражается предупреждением в интерфейсе при малом числе
  результатов.

## AI/API

- Wikimedia Commons API + Openverse API — поиск изображений (без ключей).
- Google Gemini API (vision + text) — верификация фото и генерация описания.
- Wikipedia REST/Search API — разрешение неоднозначности и факт-база.
